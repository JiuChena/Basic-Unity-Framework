# CoreFramework Layer

这一层承载通用基础设施，但并不是所有子模块都属于“行为编辑器最小迁移集”。

## 当前子模块分层

### 行为系统强依赖

以下子模块当前已被 `Framework/SkillCore` 或 `Framework/RPGGameplay` 直接引用，迁移行为系统最小闭环时必须一起带走：

- `事件中心模块`
  - 提供 `TypedEventBus`、`EventCenter`、`EventNames`

- `对象池模块`
  - 提供 `ObjectsPool`

- `特效管理模块`
  - 提供 `VFXPool`

当前状态补充：

- `SkillCore` / `RPGGameplay` 当前对这几块能力的调用分成两类：
  - 强类型运行时通知直接使用 `TypedEventBus`
  - 对象池、单位特效生成通过 `RpgFrameworkPresentationBridge` 收敛
- 当前桥接层只保留表现层资源访问入口：
  - `IRpgPresentationBridge`
- 这意味着下一步如果继续纯化框架，应优先继续判断“哪些能力值得桥接、哪些能力应直接直连”，而不是为所有静态设施统一再包一层

### 条件性依赖

以下子模块是否需要迁移，取决于项目侧桥接实现是否继续复用当前默认规则：

- `音频管理模块`
  - 如果项目侧 `IBehaviorEventReceiver` 仍直接沿用当前音频播放链路，则通常需要一起迁移

- `HSM`
  - 如果项目侧状态机继续复用当前 HSM 实现，则需要一起迁移

- `Input`
  - 如果项目侧玩家/AI 输入黑板链路继续沿用当前输入模型，则需要一起迁移

### 当前可选通用包

以下子模块属于可复用基础能力，但不属于当前行为编辑器运行时最小闭环的硬依赖：

- `AddressableManager`
- `UI管理模块`
- `二进制数据管理器`
- `交互系统`
- `任务系统`
- `伤害数字缓冲池`
- `公共Mono模块`
- `场景切换模块`
- `计时器事件中心`

## 迁移原则

- 如果目标是“整套 RPG 基础框架复用”，可直接迁移整个 `CoreFramework`
- 如果目标是“只把行为编辑器和行为解释器摘出来做插件”，应优先只带走强依赖子模块，再按项目需要决定是否补入条件性依赖
- 后续如果继续纯化框架，优先方向不是继续混合新增功能，而是把 `CoreFramework` 拆成“行为系统基础包”和“其他通用基础包”两份更稳定的迁移单元
