# 框架设计原则

## 核心约束

1. **修改基础框架是高风险操作**，必须征求用户同意
2. **设计框架级功能必须先规划后实现**并审计性能
3. **业务逻辑优先检查已有功能**，禁止重复造轮子
4. **发现框架缺陷及时反馈**，基础通用功能缺失时申请创建框架模块

## 分层

```
Expand Component/   — 可挂载组件（UnitMover, DataProvider）
Gear/               — 基础工具（EventSystem, ObjectPool, AudioManager...）
Unity Engine
```

- 组件不跨层引用另一组件的内部模块
- Profile/Settings 类纯数据，不含物理逻辑
- Motor 模块纯 C#，不依赖 MonoBehaviour

## 架构模式

- **模块化 Profile**：每个运动维度独立 Settings 类（Jump/Hover/Gravity/Locomotion/Step/FloatingCapsule/EdgeProtection）
- **纯 C# 管线**：`UnitMovementRuntime` 不依赖 MonoBehaviour，通过 `IUnitBody` 抽象刚体
- **DataProvider + Blackboard**：`IDataProvider` → `Blackboard`（可继承，Type 键）→ 策略消费
- **DataSourceHandler**：非 MonoBehaviour 的数据源处理器，`Initialize(GameObject)` 自行获取组件
- **Strategy 模式**：`UnitMovementStrategy` 子类化，运行时按类型切换并缓存实例

## 性能红线

- 零装箱：数据读写路径不允许 `object` 中转
- `FixedUpdate` 中物理模块使用预分配 `RaycastHit[]` 缓冲区
- 组件引用在 `Awake`/`OnEnable` 缓存，不在热路径查 `GetComponent`
- Profile/Settings 按需暴露只读属性，内部 `_serializedField` 私有

## 编辑器支持

- `[ExecuteAlways]` + `OnDrawGizmosSelected` 提供运行时诊断可视化
- `[SerializeReference]` 支持多态策略选择
- 自定义 Editor 在 `Framework.ExpandComponent.{ModuleName}.Editor` 命名空间
