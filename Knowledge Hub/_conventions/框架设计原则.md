# 框架设计原则

## 核心约束

1. **修改基础框架是高风险操作**，必须征求用户同意
2. **设计框架级功能必须先规划后实现**并审计性能
3. **业务逻辑优先检查 CoreFramework 已有功能**，禁止重复造轮子
4. **发现框架缺陷及时反馈**，基础通用功能缺失时申请创建框架模块

## 分层原则

```
Gameplay 层（玩法相关）
    ↓ 依赖
Core 层（平台无关的基础能力）
    ↓ 依赖
Unity Engine
```

- Core 层不引用 Gameplay 层
- Gameplay 层通过 Core 层暴露的接口/基类与具体实现交互

## 性能红线

- 零装箱：数据读写路径不允许 `object` 中转
- 避免 `Update` 中的 `GetComponent` / `FindObjectOfType`
- 物理相关逻辑在 `FixedUpdate` 中执行
- 每帧分配控制：预分配缓冲区（`RaycastHit[]`）、缓存组件引用

## 扩展性

- **Strategy 模式**：`MovementStrategy` 子类化扩展移动行为
- **Provider 模式**：`IDataProvider` 统一不同数据源
- **Attribute 注册模式**：`BlackboardAttribute<T>` + 字符串 Key 常数
- **接口 > 基类**：`IInputReader`、`IInputContextMapper`、`IInteractable`

## 编辑器支持

- `[ExecuteAlways]` 用于需要编辑时预览的组件（如 UnitMover Gizmos）
- `[RequireComponent]` 声明组件依赖
- 自定义 Editor 脚本放在 `Assets/Editor/Framework/` 镜像目录
