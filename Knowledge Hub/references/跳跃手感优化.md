# 跳跃手感优化参考

## 核心原理

好的跳跃手感不是简单的"按下 → 施加向上的力"，而是玩家意图和角色响应之间的**时间窗口匹配**。人体反应时间约 200ms，游戏帧率 60fps 意味着每帧仅 16ms——三种核心技术就是用来弥合这个差距的。

---

## 一、Coyote Time（离开边缘缓冲）

### 问题

玩家走到平台边缘后按跳，但手指按下时角色已经离地——跳不出来，非常挫败。

### 方案

角色离地后的短暂时间窗口（通常 **0.08~0.15s**）内，仍视为"可跳跃"。计时器在接地时重置为最大值，离地后递减。

```csharp
// PlayerDataProvider 侧：只负责读按钮状态
// UnitMover 侧：跳跃判断逻辑
private float _coyoteTimer;
private const float CoyoteTime = 0.12f;

// FixedUpdate 中：
_coyoteTimer = _isGrounded ? CoyoteTime : _coyoteTimer - Time.fixedDeltaTime;

// 跳跃判断：
bool canJump = _coyoteTimer > 0f;
```

### 参数参考

| 游戏 | Coyote Time |
|------|------------|
| Celeste | ~0.08s（5帧@60fps） |
| Hollow Knight | ~0.1s |
| Super Meat Boy | ~0.2s |
| **推荐起步值** | **0.1~0.12s** |

## 二、Jump Buffer（预输入缓冲）

### 问题

玩家在落地前一瞬间按跳，但按键发生在落地之前，输入被丢弃——角色不跳，玩家觉得"我明明按了"。

### 方案

跳跃键按下时如果角色在空中，记录一个时间窗口（**0.1~0.2s**），落地瞬间自动触发跳跃。

```csharp
private float _jumpBufferTimer;
private const float JumpBufferTime = 0.15f;

// 在 Update() 中（不丢输入）：
if (jumpPressed && !_isGrounded)
    _jumpBufferTimer = JumpBufferTime;

// 在 FixedUpdate() 中：
_jumpBufferTimer -= Time.fixedDeltaTime;

// 接地时：
if (_isGrounded && _jumpBufferTimer > 0f)
{
    ExecuteJump();
    _jumpBufferTimer = 0f;
}
```

### 与 Coyote Time 的组合

两者不冲突，取并集：**coyote 允许离地后跳，buffer 允许落地前预输入**。合并判断：

```csharp
bool jumpRequested = _jumpPressed || _jumpBufferTimer > 0f;
bool canJump = _coyoteTimer > 0f;

if (jumpRequested && canJump)
{
    ExecuteJump();
    _jumpBufferTimer = 0f;
    _coyoteTimer = 0f;
}
```

## 三、Variable Jump Height（可变跳跃高度）

### 问题

短按和长按跳跃键，角色跳到同样的高度——缺少可控性。

### 两种主流实现

#### 方案 A：早期释放速度裁剪（简单，但有小风险）

松开按键时如果仍在上升，将当前上升速度乘以一个系数砍掉一部分：

```csharp
// 在 Update() 中检测按键松开（不能放 FixedUpdate，会丢事件）
if (jumpReleased && _isJumping && _rigidbody.velocity.y > 0f)
{
    Vector3 velocity = _rigidbody.velocity;
    velocity.y *= 0.5f; // 砍掉一半上升速度
    _rigidbody.velocity = velocity;
}
```

**风险**：如果 `GetKeyUp` 在帧间被错过（极短的点击），可能漏掉裁剪，导致跳得比预期高。解决：限制最大跳跃时间。

#### 方案 B：重力倍率切换（推荐，更平滑）

上升期间按住跳跃键 → 使用较小重力（上升更持久）。松开按键或超过最大按住时间 → 切换到较大重力（快速到顶）。

```csharp
// 跳跃上升阶段的重力控制
private const float JumpHoldGravity = 1.0f;   // 按住时的重力倍率（正常）
private const float JumpReleaseGravity = 3.0f; // 松开后的重力倍率（快速回落）

private float _currentJumpGravity = 1.0f;
private float _jumpHoldTimer;
private const float MaxJumpHoldTime = 0.3f; // 最大按住时间，防止无限上升

// FixedUpdate 中：
if (_isJumping && _jumpHoldTimer < MaxJumpHoldTime)
{
    if (jumpHeld)
    {
        _currentJumpGravity = JumpHoldGravity;
        _jumpHoldTimer += Time.fixedDeltaTime;
    }
    else
    {
        _currentJumpGravity = JumpReleaseGravity;
    }
}

// 应用重力时：
_rigidbody.AddForce(Physics.gravity * gravityMultiplier * _currentJumpGravity, ForceMode.Acceleration);
```

**优势**：不直接操作 velocity，与物理引擎配合更自然；不存在"漏事件"问题。

## 四、刚体质量与"软绵绵"跳跃的关系

### 核心结论：质量对跳跃手感几乎无影响

当前 UnitMover 使用的 ForceMode 链条：

| 操作 | ForceMode | 是否受 mass 影响 |
|------|-----------|:---:|
| 跳跃初速 | `ForceMode.VelocityChange` | ❌ 无视 mass |
| 地面弹簧 | `ForceMode.Acceleration` | ❌ 无视 mass |
| 水平移动 | `ForceMode.VelocityChange` | ❌ 无视 mass |
| 自定义重力 | `ForceMode.Acceleration` | ❌ 无视 mass |

**`ForceMode.VelocityChange`** = 直接加 `deltaV`，不走 `F=ma`，mass 被绕过。
**`ForceMode.Acceleration`** = 直接加加速度，同样无视 mass。

所以 Rigidbody.mass 调多少，跳跃高度完全不变。

### 那为什么跳跃看起来软绵绵？

三个真实原因，按影响力排序：

#### 1. 重力太小

当前 `gravityMultiplier = 1.0`，乘以 `Physics.gravity` 默认 `-9.81`。平台游戏的标准是 **15~25**。

```
真实物理 (9.81)  → 角色像在月球上飘
平台游戏 (15-20) → 起落干脆有力
格斗游戏 (25-35) → 极快起落，几乎没有浮空
```

UnitMover 直接把 `gravityMultiplier` 调到 **1.8~2.5**，跳跃立刻变硬朗。

#### 2. 下落阶段重力没有加速

即使上升阶段重力合适，下落过程如果用同一个重力值，角色从顶点掉下来还是太慢。解决方案：

```csharp
// 上升时
float gravity = Physics.gravity.y * gravityMultiplier;           // 正常
// 下落时（velocity.y < 0）
float gravity = Physics.gravity.y * gravityMultiplier * 2.0f;   // 加倍，快速砸地
```

这就是可变跳跃高度的方案 B 的下落部分——上升和下落用不同重力。

#### 3. Rigidbody.drag 可能不是 0

`ConfigureRigidbody()` 里只设置了 `isKinematic`、`useGravity`、`interpolation`、`collisionDetectionMode`——**没有设置 drag**。

如果用户在 Inspector 里给 Rigidbody 设了非零 drag，下降时就会有空气阻力，像降落伞。应在 `ConfigureRigidbody()` 中显式归零：

```csharp
_rigidbody.drag = 0f;
_rigidbody.angularDrag = 0f;
```

### 质量什么时候才需要调？

只有在以下场景 mass 才有意义：

- 用 `ForceMode.Force` 或 `ForceMode.Impulse`（走 `F=ma`）
- 角色需要推动其他 Rigidbody 物体（`OnCollision` 推动物）
- 需要角色之间有碰撞质量差异（重角色推动轻角色）

对纯移动/跳跃的手感来说，**调 mass 只是浪费时间**。

## 五、公式化跳跃参数

与其手动调 `jumpSpeed` 和 `gravity`，不如从设计参数反推物理值：

| 设计参数 | 含义 | 示例值 |
|---------|------|--------|
| `jumpHeight` | 期望最大跳跃高度（米） | 2.5m |
| `timeToPeak` | 上升到顶点的时间（秒） | 0.35s |
| `timeToFall` | 从顶点落回的时间（秒） | 0.25s |

推导公式：

```
gravityAscent  = (2 × jumpHeight) / (timeToPeak²)
jumpVelocity   = gravityAscent × timeToPeak
gravityFall    = (2 × jumpHeight) / (timeToFall²)
```

这样设计师调的是"高度"和"时间"这些直觉参数，而不是原始物理值。

## 六、UnitMover 当前跳跃实现分析

当前 UnitMover 的跳跃逻辑（`ApplyJumpRequest`）：

```csharp
// 沿地面法线施加初始速度（支持斜坡跳跃）
float normalVelocity = Vector3.Dot(_rigidbody.velocity, _groundNormal);
float velocityChange = Mathf.Max(0f, jumpSpeed - normalVelocity);
_rigidbody.AddForce(_groundNormal * velocityChange, ForceMode.VelocityChange);

// 跳跃后短暂忽略地面检测，避免立即判定为接地
_groundIgnoreUntil = Time.time + JumpGroundIgnoreDuration; // 0.1s
```

**已具备**：沿法线跳跃（斜坡正确处理）、跳跃后地面忽略、`ForceMode.VelocityChange` 无视 mass ✅

**缺少**：Coyote Time、Jump Buffer、Variable Jump Height、设计参数公式化、升/降不同重力、显式 drag=0

## 七、建议实现优先级

| 优先级 | 技术 | 复杂度 | 收益 |
|--------|------|--------|------|
| 1 | `gravityMultiplier` 调至 1.8~2.5 | 零代码 | 立竿见影——跳跃不再飘 |
| 2 | `drag = 0` 显式归零 | 一行代码 | 防止 Inspector 误设 |
| 3 | Jump Buffer | 低（一个 timer） | 高——解决"按了没反应" |
| 4 | Coyote Time | 低（一个 timer） | 高——解决"边缘没跳到" |
| 5 | 升/降不同重力（方案 B） | 中（重力状态机） | 高——下落干脆 + 可变高度 |
| 6 | 公式化参数 | 低（改 Inspector） | 中——方便调参
