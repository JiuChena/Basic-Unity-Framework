# 输入系统 → 数据驱动框架 整改建议

> **状态**：设计定稿，待实现  
> **范围**：`Assets/Scripts/C#/Framework/Core/Input/` 全部文件  
> **关联模块**：`UnitMover`、`MovementStrategy` 及各消费输入的业务系统  
> **核心原则**：零装箱、全泛型、无 object 类型数据读写

---

## 一、现状与问题

### 1.1 当前架构

```
IInputProvider (接口)              Blackboard (具体类)
    │                                   │ Dictionary<Type, IBlackboardData>
    ├── BaseInputProvider (抽象Mono)    │  ├── LocomotionInputData
    │   ├── PlayerInputProvider        │  ├── CombatInputData
    │   └── AIInputProvider            │  └── InteractionInputData
    │                                   │
    └── Tick() → 写入 Blackboard       │
                                        ▼
                                  MovementStrategy.Execute(board, mover)
```

### 1.2 核心问题

| # | 问题 | 说明 |
|---|------|------|
| 1 | **命名误导** | "Input"暗示只处理玩家设备输入，但 `AIInputProvider` 不读任何物理设备——它做的是程序化决策，本质是**数据源**而非输入 |
| 2 | **Blackboard 封闭** | `Dictionary<Type, IBlackboardData>` 按类型索引，新增数据槽必须定义新类、现有类型只能存一个实例，无法灵活扩展属性 |
| 3 | **三层管线过重** | `InputSystemReader` → `InputActionStateStore` → `StandardInputContextMapper` → `Blackboard` 四步才到达领域数据，AI 侧又完全不走这条链路，结构不对称 |
| 4 | **Provider 职责模糊** | `BaseInputProvider` 既管设备读取又管管线构造，380 行混杂了 Legacy/InputSystem 兼容、Inspector 序列化、数据转换 |
| 5 | **属性无自描述** | `LocomotionInputData.Move` 只是一个 `Vector2` 属性，没有"我是什么、谁来写、怎么校验"的元信息 |

---

## 二、整改目标

将"输入系统"重构为**通用的数据驱动框架**，核心思路：

> 任何挂载在实体上的数据模块（玩家/敌人/NPC/可交互物）都通过同一套接口，从各自的数据源获取数据，写入一个可扩展的属性黑板，供下游系统统一消费。

## 四、核心类型定义（定稿）

### 4.1 `BlackboardAttribute<T>` — 唯一的属性基类

不再分离非泛型/泛型两个接口。只有一个抽象类，属性继承它。

```csharp
namespace CoreFramework
{
    /// <summary>
    /// 黑板属性的抽象基类。
    /// 每个属性子类定义自己的 KEY 常量和数据类型 T。
    /// 通过 .Value 直接读写，零装箱。
    /// </summary>
    public abstract class BlackboardAttribute<T>
    {
        /// <summary>
        /// 属性的唯一字符串标识。
        /// 子类通过 public const string KEY 暴露，注册和查找都使用此常量。
        /// </summary>
        public abstract string Key { get; }

        /// <summary>
        /// 类型安全的属性值。外部直接 get/set，无装箱。
        /// 子类可在 setter 中追加校验/Clamp/事件通知逻辑。
        /// </summary>
        public T Value { get; set; }
    }
}
```

关键设计决策：
- **class 而非 struct**：属性实例只在注册时分配一次，后续只读写 `Value`（`T` 是 struct 如 `Vector2` 时零 GC）
- **没有非泛型基接口**：不存在 `IBlackboardAttribute`、不存在 `GetRawValue(): object`、不存在 `SetRawValue(object)`
- **`abstract string Key`**：强制每个属性子类必须返回自己的标识——这个标识就是 `public const string KEY` 的值

### 4.2 `Blackboard` — 可继承基类

```csharp
namespace CoreFramework
{
    /// <summary>
    /// 基于字符串键的属性存储。
    /// 内部用 Dictionary<string, object> 存属性实例引用（非数据值），
    /// 对外所有方法均为泛型，编译时类型安全，零装箱。
    /// </summary>
    public class Blackboard
    {
        // 存储的是属性实例的引用（class），而非数据值本身。
        // object 仅作为引用容器，读写 Value 时通过泛型方法取出强类型引用后直接操作 T Value。
        private readonly Dictionary<string, object> _attrs = new Dictionary<string, object>();

        /// <summary>注册一个属性实例。Key 取自 attr.Key。</summary>
        public void Register<T>(BlackboardAttribute<T> attr)
        {
            if (attr == null) throw new ArgumentNullException(nameof(attr));
            if (string.IsNullOrEmpty(attr.Key))
                throw new ArgumentException("Attribute key must not be null or empty.");
            _attrs[attr.Key] = attr;
        }

        /// <summary>移除指定属性</summary>
        public bool Remove(string key) => _attrs.Remove(key);

        /// <summary>
        /// 获取指定类型的属性实例。
        /// 返回 null 表示未注册或类型不匹配。
        /// </summary>
        public TAttr Get<TAttr>(string key) where TAttr : class
        {
            if (_attrs.TryGetValue(key, out object obj) && obj is TAttr attr)
                return attr;
            return null;
        }

        /// <summary>尝试获取属性实例</summary>
        public bool TryGet<TAttr>(string key, out TAttr attr) where TAttr : class
        {
            if (_attrs.TryGetValue(key, out object obj) && obj is TAttr typed)
            {
                attr = typed;
                return true;
            }
            attr = null;
            return false;
        }

        /// <summary>检查属性是否已注册</summary>
        public bool Has(string key) => _attrs.ContainsKey(key);

        /// <summary>清空全部属性</summary>
        public void Clear() => _attrs.Clear();
    }
}
```

### 4.3 `IDataProvider` — 接口

精简到最核心的两个职责：持有黑板 + 采集数据。

```csharp
namespace CoreFramework
{
    /// <summary>
    /// 数据提供器接口。
    /// 每个拥有数据的实体挂一个实现此接口的 MonoBehaviour。
    /// 消费方通过 Blackboard 直接读取属性，或通过 Provider 的泛型辅助方法。
    /// </summary>
    public interface IDataProvider
    {
        /// <summary>当前实体持有的黑板</summary>
        Blackboard Blackboard { get; }

        /// <summary>每帧采集数据源，处理并写入 Blackboard 中的属性</summary>
        void Tick();
    }
}
```

### 4.4 `DataProviderBase` — 抽象 MonoBehaviour

```csharp
namespace CoreFramework
{
    /// <summary>
    /// IDataProvider 的抽象 MonoBehaviour 基类。
    /// 封装 Blackboard 持有和泛型代理写入方法。
    /// 子类需要：① Awake 中创建 Blackboard 并注册属性；
    ///           ② Tick() 中采集数据源，写入 Blackboard 属性。
    ///
    /// 写入方式二选一（实现时决定）：
    ///   方式一：Awake 时缓存属性引用 → Tick 中 _cachedXxx.Value = ...（零字典查找）
    ///   方式二：Tick 中调用 SetValue(key, value)（一个泛型方法覆盖所有类型）
    /// </summary>
    public abstract class DataProviderBase : MonoBehaviour, IDataProvider
    {
        public abstract Blackboard Blackboard { get; }

        protected virtual void Update() => Tick();

        public abstract void Tick();

        /// <summary>
        /// [方式二] 泛型代理写入：通过 key 查找属性并直接赋值 .Value。
        /// T 由传入的 value 自动推断，调用方无需显式指定类型。
        /// 选方式一时此方法不保留。
        /// </summary>
        protected void SetValue<T>(string key, T value)
        {
            var attr = Blackboard?.Get<BlackboardAttribute<T>>(key);
            if (attr != null) attr.Value = value;
        }
    }
}
```

注意：
- `IDataProvider` 上没有 Get/Set 方法——那是 Blackboard 的职责
- `DataProviderBase` 提供 `protected GetAttribute<TAttr>()` 作为便捷方法，子类在 `Tick()` 内部用它快速找到属性实例然后直接赋 `.Value`
- 外部消费方直接用 `Blackboard.Get<TAttr>(key)` 获取属性读 `.Value`

### 4.5 具体属性示例：`MoveAttribute`

```csharp
namespace CoreFramework
{
    /// <summary>
    /// 移动输入属性。值为二维移动输入向量。
    /// setter 自动归一化到单位圆内。
    /// </summary>
    public sealed class MoveAttribute : BlackboardAttribute<Vector2>
    {
        /// <summary>字符串常量，所有引用方通过此常量寻址，杜绝拼写错误</summary>
        public const string KEY = "Move";

        public override string Key => KEY;

        private Vector2 _value;
        public override Vector2 Value
        {
            get => _value;
            set => _value = value.sqrMagnitude > 1f ? value.normalized : value;
        }
    }
}
```

### 4.7 具体 DataProvider 示例：`PlayerDataProvider`

```csharp
namespace CoreFramework
{
    /// <summary>
    /// 玩家数据提供器。数据源：设备输入（Input System / Legacy）。
    /// 在 Tick() 中从设备读取原始值 → 处理 → 写入 Blackboard 属性。
    ///
    /// 实现时可二选一：
    ///   方式一：Awake 缓存属性引用，Tick 中 _cachedXxx.Value = ...（零字典查找，需声明字段）
    ///   方式二：Tick 中 SetValue(key, value)（一个泛型方法全覆盖，无需额外字段）
    /// </summary>
    public sealed class PlayerDataProvider : DataProviderBase
    {
        [Header("输入配置")]
        [SerializeField] private InputBindingProfile _bindingProfile;

        private Blackboard _board;
        public override Blackboard Blackboard => _board;

        // [方式一] 缓存的属性引用
        private MoveAttribute  _cachedMove;
        private LookAttribute  _cachedLook;
        private JumpAttribute  _cachedJump;
        // ...

        protected override void Awake()
        {
            _board = new Blackboard();

            // [方式一] 创建并缓存
            _cachedMove = new MoveAttribute();
            _cachedLook = new LookAttribute();
            _cachedJump = new JumpAttribute();
            _board.Register(_cachedMove);
            _board.Register(_cachedLook);
            _board.Register(_cachedJump);

            // [方式二] 直接 new 注册，不缓存
            _board.Register(new AimAttribute());
            _board.Register(new SprintAttribute());
        }

        public override void Tick()
        {
            // [方式一] 缓存引用直写（零字典查找）
            _cachedMove.Value = ReadMoveInput();
            _cachedLook.Value = ReadLookInput() * lookSensitivity;
            var jumpState = new InputButton();
            jumpState.SetState(ReadJumpPressed(), ReadJumpHeld(), ReadJumpReleased());
            _cachedJump.Value = jumpState;

            // [方式二] 泛型 SetValue（一个方法覆盖所有类型）
            SetValue(AimAttribute.KEY,    ReadAimHeld());     // T = bool
            SetValue(SprintAttribute.KEY, ReadSprintHeld());  // T = bool
        }
    }
}
```

### 4.8 具体 DataProvider 示例：`AIDataProvider`

```csharp
namespace CoreFramework
{
    /// <summary>
    /// AI 数据提供器。数据源：导航系统 + 程序化行为决策。
    /// 与玩家走完全相同的 Blackboard 属性体系。
    /// </summary>
    public sealed class AIDataProvider : DataProviderBase
    {
        private Blackboard _board;
        private MoveAttribute _cachedMove;
        private JumpAttribute _cachedJump;
        private AttackAttribute _cachedAttack;
        // ...

        public override Blackboard Blackboard => _board;

        protected override void Awake()
        {
            _board = new Blackboard();
            // 注册与玩家相同的属性集
            _cachedMove = new MoveAttribute();
            _cachedJump = new JumpAttribute();
            _cachedAttack = new AttackAttribute();
            _board.Register(_cachedMove);
            _board.Register(_cachedJump);
            _board.Register(_cachedAttack);
        }

        public override void Tick()
        {
            // AI 决策 → 写入同一个属性体系
            _cachedMove.Value = CalculatePatrolDirection();
            _cachedJump.Value.SetState(ShouldJump(), false, false);
            _cachedAttack.Value.SetState(ShouldAttack(), IsAttacking(), false);
        }
    }
}
```

## 五、装箱分析验证

### 整个数据读写路径，每一步类型检查：

```
Tick():  _cachedMove.Value = new Vector2(1, 0);
//        ↑ MoveAttribute 引用（无查找）   ↑ Vector2 是 struct，直接写入字段，无装箱

策略消费: var attr = board.Get<MoveAttribute>(MoveAttribute.KEY);
//         ↑ Dictionary<string, object>.TryGetValue 取出 object 引用
//         ↑ "obj is TAttr" 类型检查（一次引用转换，非数据装箱）
//         ↑ 返回的是 MoveAttribute 的引用

策略读值: Vector2 input = attr.Value;
//         ↑ MoveAttribute.Value getter 返回 Vector2 struct，无装箱
```

| 操作 | 是否装箱 | 说明 |
|------|---------|------|
| `new MoveAttribute()` 存入 Dictionary | ❌ 不装箱 | 引用类型存引用 |
| `board.Get<MoveAttribute>(KEY)` | ❌ 不装箱 | 泛型约束 + `is` 引用检查 |
| `attr.Value` get | ❌ 不装箱 | Vector2 是 struct，直接字段读取 |
| `attr.Value = xxx` set | ❌ 不装箱 | Vector2 直接字段写入 |
| 整个路径 | **零装箱** | 全程泛型保护 |

内部 `Dictionary<string, object>` 的 `object` 存的始终是属性实例的**引用**（class），从来不存数据值。数据值通过泛型 `T Value` 强类型读写。

## 六、与现有架构的差异对比

| 维度 | 现有（Input 系统） | 新设计（DataProvider 框架） |
|------|-------------------|---------------------------|
| 顶层接口 | `IInputProvider` | `IDataProvider` |
| 命名语义 | 暗示"输入设备" | 明确"数据源" |
| Blackboard | 具体类，`Dictionary<Type, IBlackboardData>` | 可继承基类，`Dictionary<string, object>`（属性实例引用） |
| 属性定义方式 | 实现 `IBlackboardData`，类即数据槽 | 继承 `BlackboardAttribute<T>`，含 Key 常量 + 类型化 Value |
| 属性读写 | 外部直接 set 属性：`data.Move = ...` | 外部读 `.Value`，Provider 写 `.Value`，零中间层 |
| 扩展新属性 | 新建类 + 新字段 + 修改消费方 | 新建属性类（含 KEY 常量），注册到 Blackboard，消费方引用 KEY |
| 数据管线 | `Reader → StateStore → Mapper → Blackboard` | Provider 直接处理 → Blackboard 属性 `.Value` |
| AI vs 玩家 | 两条不同的类 | 同一接口，同一属性体系，仅数据源不同 |
| 类型 Key | `typeof(LocomotionInputData)` | `MoveAttribute.KEY`（字符串常量） |
| 装箱 | 当前也无（struct 字段直接访问） | 零装箱 |

## 七、数据流对比

### 现有流程（玩家）

```
Input.GetKey / PlayerInput
    │
    ▼
BaseInputProvider.ReadMoveInput()     ← 设备读取（混在 Provider）
    │
    ▼
DelegateInputReader / InputSystemReader ← 适配层
    │
    ▼
InputActionStateStore.SetVector2()     ← 中间状态存储
    │
    ▼
StandardInputContextMapper.Write()     ← 翻译层
    │
    ▼
board.GetOrCreate<LocomotionInputData>().Move = ...
    │
    ▼
MovementStrategy.Execute(board, mover)
```

### 新设计流程（玩家）

```
PlayerInput / InputSystem
    │
    ▼
PlayerDataProvider.Tick()              ← 设备读取 + 数据处理
    │
    ├─ ReadMoveInput() → Vector2
    ├─ 归一化等处理
    └─ _cachedMove.Value = processed    ← 直接写入，无中间层
    │
    ▼
MovementStrategy 读 Blackboard：
    var attr = board.Get<MoveAttribute>(MoveAttribute.KEY);
    Vector2 move = attr.Value;
```

### 新设计流程（AI）

```
导航系统 / 行为树 / 程序化决策
    │
    ▼
AIDataProvider.Tick()                   ← AI 决策
    │
    ├─ CalculatePatrolDirection() → Vector2
    ├─ ShouldJump() → button state
    └─ _cachedMove.Value / _cachedJump.Value.SetState(...)
    │
    ▼
与玩家完全相同的 Blackboard → 策略消费路径
```

## 九、UnitMover 适配方案

### 第一步（本次）：简单适配

`MovementStrategy.Execute` 签名不变，UnitMover 只改输入源引用类型：

```csharp
// 旧
[RequireInterface(typeof(IInputProvider))]
public MonoBehaviour inputProviderSource;
private IInputProvider _inputProvider;

// 新
[RequireInterface(typeof(IDataProvider))]
public MonoBehaviour dataProviderSource;
private IDataProvider _dataProvider;
```

策略内部从 `Blackboard` 读属性替代直接读 `IBlackboardData`：

```csharp
// 旧
if (!board.TryGet(out LocomotionInputData locomotion)) return;
Vector2 input = locomotion.Move;

// 新
var moveAttr = board.Get<MoveAttribute>(MoveAttribute.KEY);
if (moveAttr == null) return;
Vector2 input = moveAttr.Value;
```

## 十一、命名规范约定
