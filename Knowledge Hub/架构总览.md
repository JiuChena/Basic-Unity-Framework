# 架构总览

## 分层

```text
Unity Scene / Prefab / ScriptableObject 配置
                │
                ├── Preloader
                ├── GameplayAbilitySystem
                ├── Interactable / InteractSearcher
                └── BehaviorExecutor 的业务宿主
                │
Gameplay 层 ────┼── GAS：能力运行时、输入共享数据、BHSM 接入
                ├── BetterHSM：状态实例与状态图仲裁
                ├── BehaviorEditor：行为 Clip 与轨道执行器
                └── Interaction：范围交互与选项视图
                │
Gear 层 ────────┼── Addressables Lease / Scope
                ├── ObjectsPool / VFXPool / Audio
                ├── EventCenter / Timer / PublicMono
                ├── BinaryData / InternetMessage
                ├── PanelManager / SceneLoader
                └── SmoothNormal
                │
Unity 与第三方 ─┴── Input System、Addressables、URP、Timeline、MessagePack
```

## 依赖方向

### 允许的依赖

```text
业务 Ability / 业务状态 / 业务轨道
    -> Gameplay 的公共契约
    -> Gear 的基础能力
    -> Unity / 已安装第三方库

GAS 的 BetterHSM 接入层
    -> BetterHSM 核心
    -> GAS Core

BehaviorEditor 的具体轨道
    -> BehaviorEditor Core
    -> 必要的 Gear 或业务 ExecuteSO
```

### 不允许的依赖

```text
Gear -> 具体角色、敌人、技能或 Timeline 轨道
BetterHSM 核心 -> PlayerInput、CharacterController、Animator、业务类型
BehaviorExecutor -> if/else 判断某个具体轨道类型
GameplayAbilitySystem -> 具体 Ability 内部模块、具体状态或具体移动方案
状态 A -> 直接调用状态 B 的生命周期或直接改 HSM 当前状态
```

## 容器与纯 C# 边界

### 必须挂载的组件

| 组件 | 职责 |
| --- | --- |
| `GameplayAbilitySystem` | 角色/实体的能力配置入口与生命周期转发器。 |
| `Preloader` | 启动时预加载 Addressable 资源。 |
| `Interactable` | 被交互目标的声明组件。 |
| `InteractSearcher` | 主动扫描附近目标并生成交互选项。 |
| `InteractOption` | 交互 UI 预制体上的池化选项视图。 |
| `AnimatorSegmentPlayer` 或业务动画适配组件 | AnimationTrack 需要动画播放适配时才挂载。 |

### 必须保持为纯 C# 的对象

| 类型 | 原因 |
| --- | --- |
| `AbilityRuntime` 子类 | 每个 GAS 实体独占，不应有额外挂载职责。 |
| `AbilityOwnerContext` 与 `IAbilityRuntimeData` | GAS 能力之间的共享运行时数据。 |
| `BetterHSM<TContext>` 与 `StateBase<TContext>` | 状态实例独立于 Unity 生命周期，可复用设计而不共享实体数据。 |
| `BehaviorExecutor` 与 `IBehaviorTrackExecutor` | 行为播放以业务宿主传入的 GameObject 为上下文，不强制挂载。 |
| Addressable Lease / Scope | 显式表达资源引用关系。 |

## GAS 的结构

```text
GameplayAbilitySystem (MonoBehaviour)
    ├── AbilityDefinitionSO 列表（Inspector 配置）
    │       ├── InputListenerAbilitySO
    │       ├── BetterHSMAbilitySO
    │       └── 业务 AbilitySO
    ├── AbilityOwnerContext（当前 GameObject 一份）
    └── List<AbilityRuntime>（当前实体独占）
```

`GameplayAbilitySystem` 不主动获取 CharacterController、Rigidbody、Animator、PlayerInput 或任意玩法组件。哪个 Ability 需要，哪个 Ability Runtime 在 `AbilityInit` 中自己获取并缓存；因此依赖与功能归属保持一致。

能力列表顺序是正式执行顺序。常用依赖链应按生产者在前、消费者在后的顺序排列，例如：

```text
InputListenerAbilitySO
BetterHSMAbilitySO
读取输入或状态的业务 AbilitySO
```

## Ability 的数据边界

每个实体只有一个 `AbilityOwnerContext`，其中维护：

```text
AbilityRuntimeDataType -> IAbilityRuntimeData
```

数据由生产者 Ability 在初始化时 `Register`，在销毁时使用同一实例 `Unregister`。消费者通过：

```csharp
OwnerContext.TryGet(AbilityRuntimeDataType.Input, out InputRuntimeData input);
```

读取。不要让消费者持有生产者 Runtime；不要把临时数据放回 ScriptableObject；不要跨实体共享 RuntimeData。

## BetterHSM 的结构

```text
BetterHSMAbilityRuntime
    -> BetterHSMAbilitySchemeCatalog.Create(...)
        -> 注册方案工厂
            -> EntityStateContext（当前实体一份）
            -> BetterHSM<EntityStateContext>（当前实体一份）
            -> StateBase<EntityStateContext> 实例（当前实体一组）
            -> StateGraphBuilder.Build(initialState)
```

状态类型可以在多个实体间复用，但**状态实例绝不能复用**。一个 `BetterHSM<TContext>` 只有一个 `TContext`，它的全部状态共享该 Context。

## BehaviorEditor 的结构

```text
Timeline Authoring Asset
    -> IBehaviorTimelineTrackCompiler（每种轨道独立）
        -> BehaviorClip
            -> BehaviorTrackData（每种数据类型一个权威实例）
                -> IBehaviorTrackExecutor（每次播放创建）
                    -> 业务 ExecuteSO / 业务组件
```

轨道编译器使用 `BehaviorTrackCompilerAttribute` 和 `TypeCache` 自动发现。新增轨道不应修改 `BehaviorExecutor`、窗口中的轨道分发代码或集中式注册表。

## 命名空间约定

当前代码已经存在两组公共命名空间，新增代码应以所在子系统的实际命名空间为准：

| 范围 | 当前命名空间 |
| --- | --- |
| Gear、BetterHSM、Interaction | `Core.Gear` |
| GAS | `Framework.Gameplay.Abilities`，配置 SO 使用 `Framework.Gameplay.Abilities.Configuration`，输入运行时使用 `Framework.Gameplay.Abilities.Input`。 |
| BehaviorEditor 运行时 | `BehaviorEditor` |
| BehaviorEditor 编辑器 | 多数为 `BehaviorEditor.Editor` 或局部编辑器命名空间，以同目录现有代码为准。 |

不要为了“统一命名”在无明确迁移计划时批量重命名。Unity 序列化引用和大量现有 using 会使这种改动风险很高。
