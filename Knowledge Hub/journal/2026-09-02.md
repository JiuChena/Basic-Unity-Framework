# MessagePack 序列化链路清理

- `AudioData` 已使用 `[MessagePackObject]` 和稳定的 `[Key]`，当前不需要重复手写 `AudioDataFormatter`。
- 删除项目级 `ProjectSaveResolver` 与音频 Formatter 注册链路，避免通用 `BinaryDataManager` 依赖 `AudioModuleManager`。
- `MessagePackRuntime` 仅使用项目已有的 `UnityResolver.InstanceWithStandardResolver`，由 Unity Resolver 处理 Unity 类型并回退 MessagePack 标准 Resolver。
- 旧数据不主动迁移；只要不修改已有 Key、不复用废弃 Key、不改变字段类型，新增字段继续追加 Key 即可保持数组字段兼容。
- IL2CPP 的 AOT 兼容属于 MessagePack Formatter 生成/解析能力问题，不通过重复业务 Formatter 解决；若正式构建暴露 AOT 缺失，再单独引入官方生成链路。

# BehaviorEditor 播放配置与作者期会话收紧

- 删除伪装为运行时轨道数据的 `BehaviorMetaData`；`BehaviorClip` 改为独立持有 `BehaviorPlaybackSettings`，保存时长、`WrapMode` 与速度倍率。Meta Timeline 轨道继续作为作者入口，但只向导出上下文写入播放配置，不再产生空执行器。
- 已迁移现有 `TimelineBehaviorClip.asset`：移除旧 Meta 的 `SerializeReference` 条目，将原有时长、包裹模式和速度写入 `playbackSettings`，避免删除类型后出现 Missing Managed Type。
- `BehaviorAuthoringParticipantCatalog` 只缓存可自动发现的参与者类型；每个 `BehaviorAuthoringSessionContext` 单独创建并持有参与者实例。重复开始作者期时先清理旧会话，避免临时 Animator 等资源失去所有者。
- 会话结束顺序固定为：轨道参与者逆序 `EndAuthoring` → 停止/解绑/按需销毁 `PlayableDirector`。参与者可以安全撤销自己的 Director 绑定或临时预览对象。
- Hitbox Scene 预览的 Reference Root 只在当前活跃作者期会话中可用，并校验 Unity Timeline 当前 inspected asset；切换其他 Timeline 或关闭片段 Inspector 后不会借用旧窗口的根节点。
