# 输入系统重构 — 架构决策

## 背景

现有 Input 系统存在命名误导（"Input"不适用于 AI）、Blackboard 封闭（Type Key 限制扩展）、三层管线过重等问题。

## 决策

### D1: 命名变更

`IInputProvider` → `IDataProvider`
**理由**: AI 侧不读设备，本质是数据源而非输入。

### D2: Blackboard 属性注册

`Dictionary<Type, IBlackboardData>` → `Dictionary<string, object>` + `BlackboardAttribute<T>` 属性基类
**理由**: Type Key 限制同类型多实例，String Key + 属性常量更灵活。

### D3: 零装箱

所有数据读写走泛型 `T Value { get; set; }`，禁止 `object GetRawValue()`
**理由**: 框架层性能红线，高频读写不允许装箱。

### D4: 旧管线全移除

`InputActionStateStore`、`StandardInputContextMapper`、`InputActionId` 等中间层全部删除
**理由**: 趁框架早期粘连少，一次性清理干净。

### D5: Provider 统一接口

玩家和 AI 走同一个 `IDataProvider` 接口
**理由**: 消费方（策略/系统）不应感知数据来源。

## 影响范围

- `Core/Input/` 全部 16 个文件 → 新建 `Core/DataProvider/`
- `UnitMover.cs` 中 `IInputProvider` → `IDataProvider`
- `MovementStrategy.Execute` 签名不变

## 当前状态

已实施。Git 提交 `d30db25` 完成 Input → DataProvider 迁移。
当前 DataProvider 架构详见 [[modules/DataProvider技能]]。

## 能力系统输入配置修订（2026-08-28）

随着单位输入迁移到 GAS 的 `InputListenerAbilityRuntime`，本决策中的旧 DataProvider 管线不再作为当前能力输入实现。当前输入链路为：

```text
InputListenerAbilitySO
    -> InputActionReference / 已有资产迁移回退
    -> InputListenerAbilityRuntime
    -> InputRuntimeData
    -> AbilityOwnerContext
    -> 其他 AbilityRuntime 消费
```

输入能力配置优先使用 `InputActionReference` 直接选择 `Move`、`Jump`、`Sprint` 等动作，避免新配置依赖字符串动作地图名和动作名。通用按钮仍使用 `InputButton` 标识映射，输入能力只采集设备输入，不包含移动、跳跃、冲刺等业务执行逻辑。

旧输入资产中的字符串字段保留为隐藏迁移回退值。Runtime 在初始化阶段解析并缓存动作，运行帧只读取已缓存的 `InputAction`，不进行动作名称查找或配置解析。新资产不应依赖这些隐藏字段。
