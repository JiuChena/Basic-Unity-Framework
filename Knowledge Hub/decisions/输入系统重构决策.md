# 输入系统重构 — 架构决策

## 背景

现有 Input 系统存在命名误导（"Input"不适用于 AI）、Blackboard 封闭（Type Key 限制扩展）、三层管线过重等问题。

## 决策

### D1: 命名变更

`IInputProvider` → `IDataProvider`
**理由**: AI 侧不读设备，本质是数据源而非输入。

### D2: Blackboard 属性注册

`Dictionary<Type, IBlackboardData>` → `Dictionary<string, object>` + `BlackboardAttribute<T>` 属性基类
**理由**: Type Key 限制同类型多实例，String Key + 属性常量更灵活。

### D3: 零装箱

所有数据读写走泛型 `T Value { get; set; }`，禁止 `object GetRawValue()`
**理由**: 框架层性能红线，高频读写不允许装箱。

### D4: 旧管线全移除

`InputActionStateStore`、`StandardInputContextMapper`、`InputActionId` 等中间层全部删除
**理由**: 趁框架早期粘连少，一次性清理干净。

### D5: Provider 统一接口

玩家和 AI 走同一个 `IDataProvider` 接口
**理由**: 消费方（策略/系统）不应感知数据来源。

## 影响范围

- `Core/Input/` 全部 16 个文件 → 新建 `Core/DataProvider/`
- `UnitMover.cs` 中 `IInputProvider` → `IDataProvider`
- `MovementStrategy.Execute` 签名不变
